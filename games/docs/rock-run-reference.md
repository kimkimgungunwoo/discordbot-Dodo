# 바위 달리기: 원작 기준과 변경 범위

## 근거

검토한 파일은 `FSAGOGUN12_scale_low.swf`(640×480, 30Hz)이다.
JPEXS 26.3.0으로 `SetGame.as`, `MapData.as` 및 심벌 좌표를 추출했다.
원작 그래픽·SWF 자체는 프로젝트에 복사하지 않는다.

## 복원한 좌표

SWF 단위인 twip을 20으로 나눈 값이다.

| 대상 | 원작 데이터 | 게임 좌표 |
|---|---|---|
| 캐릭터 | SetGame `_x=200`, `ground=365` | (200,365) |
| 발 hit_mc | shape 265 [-40,40]², sprite317 y=1 | x±2, y[-1.95,2.05] |
| 블록 | SetGame block_w=150, y=520 | 150px 단위 |
| 발판 ground_pos | shape318 x±2000,y[0,1000], translateY=-3334 | 블록 중심 x±100, y[353.3,403.3] |
| 와이어 rope_pos | shape330 x[-2200,2000],y[-1000,0], translateY=-7700 | 블록 중심 x[-110,100], y[85,135] |
| 발사 위치 | sprite317 shoot의 ropepos (250,-1088) | 캐릭터+(12.5,-54.4) |
| 스윙 몸체 기준점 | sprite317 rope의 body (286,-1119) | 캐릭터+(14.3,-55.95) |
| 기둥 외형 | sprite329 bounds[-127.5,-455,127.5,25], placement(-.05,480) | x±127.5, y25부터 |

렌더링은 위 좌표의 외형 크기에 도도새와 바위 그래픽을 배치한다.
판정은 그래픽의 투명 여백으로부터 계산하지 않는다.

## 물리와 입력

원작 정상 모드 기준 원래 프레임 단위 수식:

- 점프: dy=30; 프레임마다 dy>-20이면 dy-=3.5; y-=dy.
- 촉: 화면 좌표에서 (+45,-35); y<=0이면 종료. 월드 좌표 변환에 스크롤 거리 포함.
- 발사 입력: run이면 점프, jump이면 발사. shoot/rope/spin에서 누름은 click 상태만 변경.
- 체결: dy=15; 높이125 미만 적중이면 x-=125-y-5; y=125로 고정.
- 연결: 누르면 dy>-30에서 dy-=3.5, 놓으면 dy<30에서 dy+=3.5; y+=dy.
- 방출: 높이, body 기준 각도+70도<-70도, 촉 화면x<70 조건.
- spin: dy=45, 중력5.25; 하강에 들어가면 jump로 변경해 재발사 허용.
- 착지/사망: 4×4 발 영역과 ground_pos AABB 비교, 원작 run/jump/rope 조건 유지.

특히 원작은 버튼을 놓자마자 연결 해제하지 않으며 촉도 취소하지 않는다.
원작의 상태 전환 프레임에서 dy를 사용하는 순서도 유지한다.
기존 커스텀 진자/코요테/착지버퍼/즉시 해제와 구분해야 한다.

## 원작 이식 당시 변경 (아래 최신 개정으로 대체)

1. 위 판정·물리를 기준으로 고정한다.
2. 원작 그림 대신 기존 배구 도도새·사막 배경·바위 외형을 사용한다.
3. 원작의 150px 블록 패턴 중 와이어 패턴을 더 일찍 배치한다. 스테이지 끝에서는 패턴을 중간에 자르지 않는다.
4. 원작 30Hz 프레임 실행 시간을 전역 배율2.2 (이전1.1의 두 배)로 가속한다. 수평/수직/와이어가 함께 빨라진다.

현재 검증은 원작 추출 수치와 코드 기반 대조 및 자동 입력 시뮬레이션이다.
Flash 런타임에서 발생하는 서로 다른 onEnterFrame 콜백 순서까지 실제 재생으로 대조한 것은 아니다.
픽셀/프레임 전체가 원작 실행과 동일하다는 주장은 하지 않는다.


## 화면·패턴 개정

물리 기준 화면은 640×480 그대로이며 렌더링 시야만 960×480으로 확장한다.
동일한 표시 너비에서 캐릭터와 지형은 이전의 2/3 크기로 보인다. 판정과 월드 좌표는 동일하다.
짧은 발판을 잇는 연속 점프, 점프와 와이어의 교대, 기둥 간격이 달라지는 연속 와이어를 추가했다.
와이어 뒤 중간 착지는 3개 블록(판정 폭500px)을 확보한다.
전체 코스 길이는 기존 단계별 목표 시간을 유지하도록 속도에 비례한다.

## 달리기와 물리 시간 분리 (최신)

이전 전체2.2배 배속은 폐기했다. 현재 달리기 배율2.2, 물리 시계1.1을 별도로 사용한다.
수평 이동과 월드 스크롤만 빨라지고 점프·낙하·와이어의 프레임 간격은 사용자가 승인했던 속도로 유지한다.
달리기 증가에 따른 긴 착지 거리에 맞춰 발판 길이를 늘리고 연속 기둥 사이에는 추가 빈 블록을 둔다.
도도새는 원본40×32 스프라이트를80×64로 표시하며, 아래쪽 발끝을(y=ground)에 맞춘다.
발판은 실제 x/end/y 경계대로 그린다. 기존 장식 오버행과 별도 높이357은 제거했다.

## 현재 입력·지형 기준 (2026-10-01)

위 원작 수치는 출처 기록이다. 현재 게임은 승인된 연결 후 스윙 수식과 방출 순서를 유지하면서 다음을 적용한다.

- 발사 중 손을 떼면 취소하며, spin을 포함한 공중 상태에서 다시 발사할 수 있다.
- 폭110px 기둥의 y25~480 전체에 접촉 가능하다. 기둥 안에서 발사한 경우도 잡히고 실제 접촉 좌표를 사용한다. y125 강제 보정은 없다.
- 발판을 벗어나면 추락하며 도도새 전체가 화면 아래로 내려간 y560 이후에 사망한다. 발판 측면에 닿아 위로 올라붙지 않는다.
- 150px 원작 블록 패턴 대신 단계별 물리로 검증한 짧은 점프, 일반 점프, 끝점프, 기둥1~3개 절벽을 섞는다. 스윙 물리와 속도 배율은 그대로다.
- 와이어 구간은 점프로 넘을 수 없으며 기둥 하나를 제거한 입력 탐색에서도 통과 경로가 없는 패턴을 사용한다. 이것은 검사한 입력 범위에 대한 검증이며 모든 연속 입력의 수학적 증명은 아니다.
- 금화는 성공한 입력 궤적의 공중 위치에 놓는다. 은화/금화를 명시적으로 구분하고 금화의 점수 가중치를 3배로 둔다. 단계마다 동전70%, 완주20%, 완전수집10%, 총합100,000점을 유지한다.
- 생성은 시드에 따라 검증된 패턴의 순서와 발판 길이를 섞는다. 플레이 중 경로 탐색은 실행하지 않는다.

패턴과 금화 경로 재생성: 저장소 루트에서 `games/server/node_modules/.bin/tsx games/server/scripts/generate-rock-run-patterns.ts`.
생성된 `games/shared/rock-run-patterns.ts`에는 재현용 입력도 포함한다. 테스트에서 각 입력의 착지 및 모든 금화 획득, 조기 점프 실패, 기둥 생략 실패, 여러 시드의 완주와 서버/클라이언트 일치를 검사한다.

## 수정 누적으로 인한 구조 정리

- `rock-run-config.ts`가 시뮬레이션 주기, 물리 주기, 달리기 배율, 기둥 경계 및 스윙 상수의 단일 기준이다. 수식과 연산 순서는 유지했다.
- 패턴 파일의 `GENERATED_SETTINGS`와 현재 설정을 맵 생성 전에 대조한다. 설정 변경 시 재생성이 필요하며, 생성기는 오래된 패턴으로 맵을 만들지 않고 별도 검증 코스를 사용한다. 수치 외 충돌·업데이트 순서를 변경할 때는 `PHYSICS_REVISION`도 올린다.
- `server/analysis/rock-run-search.ts`를 생성기와 테스트가 함께 쓴다. 결과는 `found`, `not-found`, `inconclusive`로 구분한다. 탐색 예산/시간 한도 초과를 기둥 생략 불가능의 근거로 사용하지 않는다. `not-found`도 지정한 탐색 전략 안에서만 경로가 없다는 뜻이다.
- 온라인 입력은 보내지 못한 누름/뗌 순서를 큐에 보관하고 실제 입력 tick을 전송할 때만 소비한다. 새 경기 동기화 시 큐를 초기화한다. 서버가 계산하는 점수를 클라이언트에서 중복 보고하지 않는다.
- `motion`이 물리 상태의 기준이다. `y`, `vy`, `grounded`, `shot`, `rope`는 화면·효과음용으로 갱신되며 물리를 역으로 재구성하는 데 쓰지 않는다. 미사용 진자 속성 및 구형 블록 패턴은 제거했다.
- 도도새의 다이빙 스프라이트 가슴 좌표를 와이어 표시 시작점으로 사용하고 캐릭터와 같은 회전을 적용한다. 물리상의 발사 위치와 스윙 기준점은 바꾸지 않는다.
