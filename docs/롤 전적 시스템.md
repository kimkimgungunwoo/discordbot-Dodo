# 롤 전적 시스템

## 개요

Riot API를 연동해 리그 오브 레전드 소환사 프로필과 최근 전적을 조회하는 기능.
즐겨찾기 계정을 DB에 저장해 반복 조회를 편리하게 한다.

| 명령어 | 동작 |
|--------|------|
| `!롤프로필` | 소환사 랭크·마스터리·최근 전적 요약 임베드 |
| `!롤전적` | 솔로랭크 또는 자유랭크 최근 10게임 상세 임베드 |

---

## DB 모델

```python
class RiotFavorite(Base):
    id              : int (PK, autoincrement)
    discord_user_id : bigint  # Discord 유저 ID (FK 아님, 인덱스만)
    puuid           : str     # Riot 계정 고유 ID
    game_name       : str
    tag_line        : str
    created_at      : datetime
```

- `(discord_user_id, puuid)` 조합으로 중복 방지
- `!롤프로필`과 `!롤전적`이 동일한 테이블을 공유한다

## API 레이어 (`riot_api.py`)

### 엔드포인트 베이스

| 상수 | 값 |
|------|----|
| `ASIA_BASE` | `https://asia.api.riotgames.com` |
| `KR_BASE` | `https://kr.api.riotgames.com` |
| `DDRAGON_BASE` | `https://ddragon.leagueoflegends.com` |

### 주요 데이터클래스

```python
RankInfo          # 큐 타입, 티어, 랭크, LP, 승/패
MasteryInfo       # 챔프 이름·키, 마스터리 레벨·포인트
QueueStats        # 최근 N판 집계 (승/패, 주 포지션, 평균 KDA)
SummonerProfile   # 위 세 가지 + puuid·레벨·프로필 아이콘
MatchResult       # 단일 게임 결과 (승패, 챔프, KDA, CS, 게임시간, 포지션)
```

### 주요 함수

```python
# 프로필 전체 조회 (랭크·마스터리·최근10판 집계까지 한번에)
async def fetch_profile(game_name, tag_line) -> SummonerProfile

# 특정 큐의 최근 N판 상세 조회
async def fetch_match_history(puuid, queue_id, count=10) -> list[MatchResult]
```

### 챔피언 캐시

`_champ_cache: dict[int, tuple[str, str]]` — champion id → (한국어 이름, 영문 key)

DDragon에서 최초 1회 로드 후 프로세스 종료까지 메모리에 유지된다.
버전 정보도 같이 캐싱하므로 재시작 전까지는 API 호출 없이 챔프 이름을 조회한다.

### 병렬 처리

`fetch_profile` 내부에서 `asyncio.gather`로 아래 요청을 동시에 보낸다:
- 소환사 정보 / 마스터리 / 솔로 매치 ID / 자유 매치 ID / 랭크 정보 / DDragon 캐시

매치 상세 조회는 `asyncio.Semaphore(5)`로 동시 요청을 5개로 제한한다.

## 명령어 플로우

```
!롤프로필 / !롤전적
    └─ RiotMenuView
         ├─ [🔍 검색] → SearchModal (닉네임 + 태그 입력)
         └─ [⭐ 즐겨찾기] → FavoritesView → FavoritesSelect (드롭다운)
                ↓
         (닉네임 + 태그 확정)
                ↓
    !롤프로필 콜백                    !롤전적 콜백
    do_fetch_profile()              do_fetch_history()
         ↓                               ↓
    build_profile_embeds()        QueueSelectView
    ProfileView (즐겨찾기 버튼)    [🏆 솔로랭크] [🏅 자유랭크]
                                         ↓
                                  fetch_match_history(puuid, queue_id)
                                         ↓
                                  build_match_embeds()  →  전송
```

## View·Modal 구조

| 클래스 | 설명 |
|--------|------|
| `SearchModal` | 닉네임·태그 입력 Modal. `callback` 파라미터로 프로필/전적 공용 재사용 |
| `RiotMenuView` | 검색·즐겨찾기 버튼 (timeout 60s). `callback`을 SearchModal에 주입 |
| `ProfileView` | 프로필 임베드 하단에 붙는 즐겨찾기 등록/제외 버튼 (timeout 300s) |
| `FavoritesSelect` | 즐겨찾기 계정 드롭다운. `callback` 파라미터로 재사용 |
| `FavoritesView` | FavoritesSelect를 감싸는 View (timeout 120s) |
| `QueueSelectView` | 솔로랭크·자유랭크 선택 버튼 (timeout 120s) |

### 콜백 패턴

`SearchModal`과 `FavoritesSelect`는 동작을 직접 구현하지 않고 `callback` 함수를 주입받는다.

```python
InteractionCallback = Callable[[RiotCog, discord.Interaction, str, str], Awaitable[None]]

# 프로필 조회 콜백
async def do_fetch_profile(cog, interaction, game_name, tag_line): ...

# 전적 조회 콜백
async def do_fetch_history(cog, interaction, game_name, tag_line): ...
```

새로운 기능(예: 인게임 정보 조회)을 추가할 때 콜백 함수만 새로 만들면 검색·즐겨찾기 UI를 그대로 재사용할 수 있다.

## 임베드 구성

### `!롤프로필` (4개 임베드)

| # | 임베드 | 색상 |
|---|--------|------|
| 1 | 소환사 헤더 + 솔로·자유 랭크 | 최고 티어 색상 |
| 2 | 챔피언 마스터리 Top 3 | 보라 (`#7B2FBE`) |
| 3 | 시즌 전체전적 (누적 W/L) | 최고 티어 색상 |
| 4 | 최근 10판 분석 (큐별 평균 KDA) | 승률 50% 이상이면 초록, 미만이면 빨강 |

### `!롤전적` (헤더 1개 + 게임당 1개, 최대 10개)

| 요소 | 내용 |
|------|------|
| 색상 | 승리 `#57F287` (초록) / 패배 `#ED4245` (빨강) |
| 썸네일 | DDragon 챔피언 아이콘 |
| 타이틀 | `✅ 승리 — 챔프이름` or `❌ 패배 — 챔프이름` |
| 필드 | KDA 수치 + 평점, CS, 게임 시간 |
| 푸터 | `#순번 · 큐 종류 · 포지션 · 닉네임#태그` |

Discord 메시지당 임베드 최대 10개 제한 때문에 헤더 포함 11개가 되면 자동으로 2번 나눠 전송한다.
