# 도도새 루미큐브 1차 버전

## 실행

- 디스코드 `!게임 루미큐브` 또는 `!게임` 드롭다운 → 참가/봇 추가 → 방장이 시작 → 게임 링크.
- 사람과 중간/어려움 봇을 섞어 2~4명. 좌석 순서대로 파랑·빨강·초록·주황, 기존 도도새 스프라이트 사용.
- 개발 화면 `/rummikub`는 로그인 없는 로컬 연습. 온라인은 `?room=...` 링크를 사용한다.
- Discord Developer Portal OAuth2 Redirects에 **기존 Activity 공개 도메인 + `/rummikub`** 추가. 개발 도메인을 쓰면 그 도메인의 경로도 등록한다. 기존 `DODO_DATABASE_URL`을 사용하며 봇 시작 시 `api/dodo/schema.sql`로 스키마를 확장한다.

## 조작과 규칙

- 테이블 바닥은 현재 차례의 좌석 색으로 표시한다. 패 배치·뽑기·턴 변경·종료 효과음과 소리 켜기/끄기 버튼을 제공한다.
- 봇은 1.1초 대기 후 0.42초 간격으로 패를 한 장씩 공개하고, 마지막 배치를 0.7초 보여준 뒤 확정한다. 온라인·연습 모드가 같은 속도를 사용한다.
- `한 장 받고 넘기기`를 누를 때 배치가 턴 시작 상태와 다르면, 먼저 `턴 초기화`를 누르라는 안내와 함께 차례 넘기기를 차단한다. 화면·서버·연습 모드에 같은 검증을 적용한다.

- 타일 드래그 또는 여러 패 선택 후 조합 앞/뒤 `+`. `⠿`는 묶음 선택. 새 조합으로 옮겨 분리할 수 있다. 테이블에 낸 자기 패는 손패 영역으로 돌려놓을 수 있다.
- 106개(4색 1~13 두 벌 + 조커 2개), 14개씩 분배. 연속 조합은 보이는 순서대로 오름/내림차순, 13→1 연결 불가.
- 첫 등록은 손패 조합만 30점 이상. 기존 조합에 추가하거나 재배열하는 것은 등록한 다음 턴부터 가능.
- 기본 턴 시간은 60초. 제한시간 만료 때 정상 배치면 자동 확정하고, 배치를 바꾸지 않았다면 1개 뽑고 넘긴다. 수정한 배치가 잘못되었다면 초안을 유지하고 15초씩 수정 시간을 준다. 온라인에서 5분간 조작이 없으면 기존 무활동 종료가 적용된다.
- 잘못된 조합만 빨간 테두리로 표시하고 수정 전에는 턴 종료를 비활성화한다. 첫 등록 30점 미달은 이번에 낸 조합과 현재 합계 점수를 표시한다. 서버에서 잘못된 제출을 거절해도 배치·손패·차례는 유지한다. 사용자가 직접 턴 초기화를 누르면 원래 배치로 돌아간다.
- 한 장 뽑기는 수정되지 않은 배치에서만 가능하다. 수정한 상태에서는 손패·배치·남은 시간·차례를 유지하고 초기화를 요청한다. 패를 확정한 턴에는 추가로 뽑지 않는다.
- 테이블 조커를 손패로 가져올 수 없다. 손패 또는 기존 테이블 패로 조합을 합법적으로 재구성하거나 분리해 조커를 회수하고 같은 턴에 다시 사용한다. 최종 조합은 모두 유효해야 하며 해당 턴에 자기 손패를 한 장 이상 낸다. 기존 조커의 숫자·색을 고정하거나 특정 손패 교체를 강제하지 않는다. [공식 규칙의 조커 회수 예시](https://rummikub.com/wp-content/uploads/2019/12/2600-English-1.pdf)를 따른다.
- 빈 손패 승리. 조커 30점, 숫자 패는 표기 숫자. 패자는 남은 패 합계만큼 감점, 승자는 그 총합을 얻는다.
- 뽑기 더미가 비고 **인원수 × 2턴** 동안 아무도 새 패를 내지 않으면 강제 종료한다. 예: 4인은 연속 8턴. 누군가 패를 확정해서 내면 카운터를 0으로 되돌린다. 임시 편집이나 취소는 진행으로 계산하지 않는다.
- 마지막 차례에는 종료 예고를 표시한다. 봇의 마지막 차례는 최소 3초 대기한다. 강제 종료 시 손패 **개수**가 가장 적은 사람은 공동 최저까지 0점, 나머지는 남은 패 점수(조커 30점)만큼 감점한다.

## 서버와 범위

- 서버가 분배·손패·순서·시간·판정을 소유한다. 개별 스냅샷에는 본인 손패만 포함하고 다른 사람은 개수만 전달한다. 관전자는 손패를 받지 않는다.
- 임시 테이블만 전송하며, 턴 시작의 확정 테이블/손패는 성공적으로 종료하기 전까지 수정하지 않는다. 재접속은 서버 초안과 남은 시간을 복구한다. 이전 경기/턴/리비전 요청을 거부한다.
- 모든 사람이 접속해야 시작. 시작 후 접속 종료 시에도 턴 시간은 흐른다. 모두 나가면 5분 뒤 게임과 봇 타이머를 정리한다.
- 중간·어려움 모두 손패 조합, 기존 조합에 붙이기, 긴 조합 분리, 그룹/연속 조합 재구성, 조커 교체·재사용을 탐색한다. 실제 두 벌의 패를 구분하며 첫 등록 제한과 최종 조커 판정을 지킨다. 낸 패 개수를 우선하고 동률이면 남은 감점이 적은 쪽을 선택한다.
- 공개 테이블과 본인 손패만 사용한다. 재구성 탐색은 중간 55ms/7천 노드, 어려움 160ms/2만4천 노드 한도이며, 제한 안에 찾은 합법 배치를 사용한다. 후보 생성과 기본 수 계산 시간은 별도다. 모든 가능한 수를 찾거나 사람 중급자와 같은 실력을 보장하는 알고리즘은 아니다.
- **전적과 포인트 랭킹을 DB에 저장한다.** 기존 LEFT/RIGHT 좌석은 유지하고 루미큐브 P1~P4 좌석과 봇 난이도를 추가한다. 봇은 경기 참가 내역에만 저장하며 플레이어 랭킹에서는 제외한다.
- 별도 라이브러리 추가 없음. 프론트 `rummikub/`, 공유 규칙 `shared/rummikub.ts`, 서버 `rummikub-room.ts`, 봇 `game/rummikub.py`.

# 봇 강화 및 승패 점수 보정

- 어려움은 전체 테이블 탐색 전에 관련 조합 두 개씩 집중 재배열하며, 같은 수의 패와 같은 잔여 점수인 선택에서는 남긴 패의 조합 가능성을 비교한다. 상대 손패와 뽑기 순서는 보지 않는다.
- 한 명이 손패를 비우면 모든 참가자의 경기를 즉시 종료한다. 나머지 순위를 위한 경기는 이어지지 않는다.
- 엔진의 원점수는 보존하고 결과 표시·Discord 결과에는 상대별 보정 점수를 전달한다. 사람끼리 100%, 중급 봇과 50%, 어려움 봇과 75%. 봇끼리는 낮은 비율을 적용한다.
- 패자마다 감점 절댓값에 비율을 곱해 반올림하고 승자는 그 합을 받는다. 봇에게 패배한 사람의 감점도 줄어든다.
- 진행 정체로 인한 강제 종료는 기존 감점 규칙을 유지한다. 최소 손패 수 참가자는 공동 최저까지 0점이다.
- `!게임 통계 → 루미큐브 · 포인트`: 누적 획득/차감 포인트와 최근 10경기, 서버/전체 포인트 랭킹. 사람전·혼합전·봇전을 같은 포인트 랭킹에 합산하며 봇 보정된 결과를 그대로 저장한다. 누적 음수도 허용한다.
- 첫 완주자 등장 시 경기 종료. 강제 종료도 최종 정산 점수를 저장한다. 중단된 경기는 참가 내역만 남기며 누적 포인트·횟수에서 제외한다. 같은 match_id는 한 번만 합산한다.
- 포인트 룰셋은 `rummikub-points-v1`. 변경 시 기존 게임처럼 활성 룰셋 단위로 기록을 분리한다.
